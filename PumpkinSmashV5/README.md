# Pumpkin Smash! — Image Reference AR 🎃

This is a new, lightweight image-target version of Pumpkin Smash! It removes the previous large skeleton-recognition AI model. Instead, it uses **MindAR image tracking** to recognize flat reference images and attach a 3D pumpkin and small Halloween decorations to the tracked image's 3D pose.

## Important: what this version recognizes

This version tracks the **actual reference image** (for example, a printed picture or a picture displayed on a computer/phone screen). It does **not** recognize a real 3D skeleton just because that skeleton resembles a skeleton picture in the reference folder. MindAR image targets are planar-image tracking, not general object recognition. It is significantly lighter than the earlier large AI object detector but requires the reference image itself to be visible to the camera.

The 3D pumpkin follows the reference image's position and orientation while that image is tracked. When the image leaves the camera view, the tracker can lose it and the pumpkin can disappear. This is image-anchored AR, not persistent environmental SLAM/world mapping.

## Folder layout

```text
pumpkin-smash/
├── index.html
├── game.js
├── styles.css
├── target-builder.html
├── target-manifest.json   # generated by the builder after you add images
├── targets.mind           # generated target database; not included until configured
└── images/
    ├── .gitkeep
    ├── README.md
    └── manifest.json      # starts with an empty images list
```

The `images/` folder is intentionally empty of photos apart from its README, placeholder, and empty `manifest.json`. Add your own `.jpg`, `.jpeg`, `.png`, or `.webp` reference images there.

## Add reference images

GitHub Pages is static hosting and doesn't provide a directory-listing API, so browser code cannot automatically discover every filename inside `images/`. The included builder supports choosing local files and loading published images listed in `images/manifest.json`.

1. Add at least **five distinct, detailed images** to `images/` in your local project folder. Good targets contain visible details, edges, and contrast. Avoid blank graphics, flat colors, repeated patterns, blurry photos, and glossy images with reflections.
2. Open the published `target-builder.html` page (or serve the project locally over `http://localhost`).
3. For the first build, use **Select reference images** and select the same local image files you put in `images/`. Multiple selection is supported. The builder sorts names alphabetically and uses the same order in its generated manifest.
4. Press **BUILD IMAGE DATABASE** and wait for compilation to finish. The browser downloads three files: `targets.mind`, `target-manifest.json`, and `images-manifest.json`.
5. Upload `targets.mind` and `target-manifest.json` to the project root beside `index.html`. Upload `images-manifest.json` into the `images/` folder and rename it to `manifest.json`. Make sure the selected original image files also exist in `images/`. Commit the changes to GitHub.
6. Open the game page on your phone, allow camera access, and press **START IMAGE AR**. Aim at one of your exact reference images. A pumpkin appears attached near the lower area of the tracked image. Tap the pumpkin to smash it.

After the first setup, the builder's **LOAD IMAGES FROM PROJECT FOLDER** button can load published images directly from `images/manifest.json`. Whenever you add, delete, or replace images, update that JSON list (or select all intended local images), rebuild, and re-upload `targets.mind` and `target-manifest.json`. The builder also downloads a fresh `images-manifest.json` that you upload as `images/manifest.json`. Target indexes align with the alphabetical order shown in `target-manifest.json`.

If you have fewer than five source images, the win goal adjusts to the number of reference targets. The builder accepts up to 30 targets; start with 5–10 for easier mobile performance.

## Hosting on GitHub Pages

1. Keep the whole `pumpkin-smash` folder in your repository.
2. Upload the project files, preserving the folder name.
3. GitHub Pages publishes the files over HTTPS, which is required for browser camera access.
4. Open `.../pumpkin-smash/target-builder.html` to compile/update targets; after building, upload the two target files to the project root and the generated image-list manifest to `images/manifest.json`.
5. Open `.../pumpkin-smash/` on your phone to play.

The runtime uses Three.js and MindAR from CDNs, so the page needs an internet connection to load these JavaScript libraries. It no longer downloads the previous 230 MB skeleton-detection model. The compiler only runs when you visit the builder and press Build.

## Gameplay

- The first time a distinct reference image is detected, the game attaches one pumpkin to that image's tracked pose.
- It can reveal up to five pumpkins per round, one per distinct target image; with fewer than five source images, the win goal adjusts to the number of targets.
- Tap the visible pumpkin to smash it. Use Reset to replay the reference targets.
- Small bats, a ghost, a mini zombie, a dancing skeleton, and a moon are attached as decorations around each active target.
- Camera tracking is optimized for one image target at a time to reduce performance overhead on mobile devices.

## Troubleshooting

- **Start AR is disabled:** the project needs `targets.mind` and a non-empty `target-manifest.json`. Run `target-builder.html`, then upload both target files.
- **Load Images From Project Folder says the list is empty:** put the exact filenames in the `images` array in `images/manifest.json`. The included `images-manifest.json` download can be renamed and uploaded there.
- **Camera is denied:** allow camera permission for the GitHub Pages site in browser settings.
- **Images don't get recognized:** try sharper pictures with unique visual features; keep the entire picture visible, steady, and well lit. The tracker recognizes the exact planar image, not a semantically similar 3D object.
- **Build is slow or fails:** begin with 5–10 reasonably sized images. Replace low-detail images, reduce giant image dimensions, and keep the builder open while it compiles.
- **A pumpkin vanishes when the target leaves view:** that's a limitation of image-target tracking. It follows the target pose while tracking, but does not independently map the room and keep the pumpkin at a fixed location after the target is lost.

## Privacy

The image builder compiles images locally in your browser. The game uses your camera locally for target tracking; it does not upload camera footage to a game backend. The 3D engine and tracker JavaScript are downloaded from their configured CDNs.
